# 给 AI 编码助手的 UI 改版指令（复制下面整段发送）

---

你现在是一名严格的**前端视觉工程师**，负责给一个已经上线运行的「非机动车违规智能监测」交管后台做 UI 视觉收敛。项目根目录就是当前工作区（Vue 3 + Vite + Tailwind + Element Plus）。

## 第一步：先读规范，不要动手

请先完整读取 `docs/DESIGN-SPEC.md`，这是本次改版的**唯一裁决标准**。读完先不要写任何代码。

## 本次任务

把现有页面从"AI 生成感明显的模板"改成"看起来像成熟商用后台"的界面。**只改视觉层，不碰业务逻辑。**

## 五条绝对红线

1. **不得修改** `src/stores/**`、`src/mock/**`、`src/router/index.js`、任何接口调用、任何数据结构。改完功能必须和现在完全一样。
2. **配色只有 5 个变量**：主色 `#4F46E5`、中性文本 `#0F172A/#475569/#94A3B8`、边框 `#E2E8F0`、白底 + 页面底 `#F8FAFC`；语义色只有三种（待办 `#B45309`、通过 `#15803D`、驳回 `#B91C1C`）。**禁止**紫色、玫瑰色、青色、渐变、毛玻璃、彩色卡片顶边/左边条。
3. **禁止 emoji**（侧边栏、按钮、标题里的全部删掉），统一换成 `@element-plus/icons-vue` 图标（已全局注册），尺寸 16px / 导航 18px。
4. **字重只有 400 和 500**，全站禁止 `font-bold / font-semibold / font-extrabold`。字号只有 4 档（16 / 14 / 13 / 12）。
5. **禁止任何 hover 位移、缩放、发光**，hover 只允许改背景色或边框色。

## 必须修掉的 5 个已确认 bug（详见规范第 8 节）

1. `card-soft` 这个类**在项目里从未被定义**（`main.css` 只有 `card-luxury`），导致历史页、摄像头页的卡片没有白底和边框。定义统一的 `.card` 并全局替换。
2. `index.html` 上的 `<html class="dark">` 和 `main.js` 里引入的 Element Plus 暗色变量，会让弹窗/消息框变暗色。移除它们。
3. 模型管理页三张改进卡片高度不齐，**第三张被容器裁切**。
4. 右下角悬浮的"拖拽至此上传"药丸和圆形 FAB **遮挡表格操作列**。
5. 表格下方大片无意义留白。
另外：`RecordsReview.vue`、`UploadDetect.vue`、`MonitorDashboard.vue`、`Analytics.vue` 都不在 router 里，本轮**不要改**它们。

## 执行方式（必须遵守，不要一次性改完所有页面）

分四步，**每完成一步停下来，告诉我改了什么、让我确认后再继续**：

- **第 1 步**：`src/assets/main.css` + `index.html` + `src/main.js` —— 建立基础（定义 `.card`、删除渐变徽章类与 hover 位移、去暗色泄漏）。
- **第 2 步**：`src/views/Layout.vue` —— 侧边栏与顶栏（去 emoji、去渐变 logo、去 hover 缩放、修顶栏按钮被裁切）。
- **第 3 步**：`src/views/HistoryReview.vue` —— **样板页**。表格按规范 6.2 执行：`table-fixed` + 明确列宽 + 表头 `whitespace-nowrap` + `sticky` + 行高固定 48px + 单元格不折行；徽章按 6.3 单行；导出按钮改白底描边（现在是实心绿色，与"已确认"语义冲突）。
- **第 4 步**：确认样板后，用同一套模式逐个改 `ModelManagement.vue`、`MetricsDashboard.vue`、`ImageDetect.vue`、`VideoDetect.vue`、`CameraDetect.vue`、`admin/UserManagement.vue`、`admin/SystemLogs.vue`，**每改完一个页面汇报一次**。

## 每步的汇报格式

1. 改了哪些文件（列出路径）
2. 每处改动一句话说明（对照规范第几节）
3. 第 1 步之后每一步都要：跑 `npm run dev`，打开对应页面截图，自查**没有元素重叠、没有文字折行、没有横向滚动条**，把截图和自查结论给我
4. 第 3 步结束后，额外跑一遍规范第 9 节的验收自查清单，逐条给出结果

## 额外要求

- **不要重构、不要拆分组件、不要引入新依赖、不要新增 Tailwind 插件**。改动越少越好，能改 class 就不要改结构。
- **不要自己发明设计**。规范没写到的地方，保持现状，并在汇报里列出来问我。
- 如果发现规范里的要求和现有实现冲突，**以规范为准**，并在汇报里说明冲突点。
- 如果某个改法会破坏现有功能，**停下来问我**，不要擅自改。
